# hcsr_newest image atlas

The scene ABI's opt-in `HCSR_PAINT_MODE_IMAGES` emits image references alongside area-grayscale materials. Each reference contains the source URI, unclipped content rectangle, object-fit/position, and opacity. Clipped vertices retain local coordinates. The host resolves assets explicitly; the scene ABI does not perform file or network access. The original grayscale paint mode remains available.

`HCSRNewestImageAtlas` belongs to the primary view. All its secondary outputs share the atlas and the frame's vertex buffer. Images render in color; text, controls, backgrounds, borders, and other paint remain area-grayscale. The mixed packet is drawn through Godot RenderingDevice on D3D12, Vulkan, and Metal, in packet order, with straight-alpha image sampling and alpha blending. Godot tracks texture uploads, draw dependencies, output mip generation, and deferred resource destruction. Grayscale-only packets retain the existing native renderer path. The CPU fallback rasterizes the same clipped triangles.

The cache uses 4096 x 4096 RGBA8 pages, allocated on demand (64 MiB each in GPU memory, plus a CPU backing image). Shelf packing reserves a one-pixel extruded border. A source is decoded once per view/resource base; repeated images reuse stable coordinates. The first GPU allocation uploads the complete page; subsequent allocations upload only their padded rectangles. Atlas texels are UNORM, consistent with the existing output's color convention. Output mipmaps remain managed by Godot; atlas mipmaps are disabled to avoid bleeding across entries.

This first stage supports PNG, JPEG, WebP, and rasterized SVG, through local Godot resource paths and data URLs. BMP data URLs are also supported. It implements fill, contain, cover, none, scale-down, and the scene's normalized object-position values. SVGs use their natural raster size. Images larger than a page are downscaled while preserving aspect ratio. Four pages bound the cache; missing, unsupported, and capacity-exceeding images use the grayscale fallback and a cached diagnostic. Files are immutable for the lifetime of this asset cache; changing the source URI loads a new entry. Natural image dimensions currently affect object-fit only; feeding decoded metadata back into auto-sized layout is a separate step. CSS background images, inline SVG painting, fonts, effects, and cache eviction are outside this stage.

Diagnostics appear under `get_frame_scheduler_diagnostics().frame_synchronization.image_atlas`: pages, sources, decoded_images, uploaded_bytes, page_size, and draw_batches. They describe asset storage and current packet batches, not a damage system. Every requested scene update still builds and draws a complete frame.

Run `modules/html_css/tests/hcsr_newest_image_atlas_smoke.gd` with the hcsr_newest editor and a project path, using D3D12, Vulkan, or Metal; pass `-- --cpu` for the CPU fallback. The test checks image color, transparency, clipping, paint order, source mutation, reuse, partial upload size, differently sized outputs, mipmaps, resizing, and release.
